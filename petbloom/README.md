# PetBloom · 宠物花园

全物种宠物饲养管理与陪伴 PWA（v1.1.0）。

> **换对话继续开发？先读 [HANDOFF.md](./HANDOFF.md)** —— 那里有完整的项目交接说明。

运行时零依赖、纯静态、离线可用 —— 因为最需要它的场景（凌晨三点发现猫吐了）往往也是网络最差的时候。

```bash
cd petbloom
npm run dev          # http://localhost:4173  开发用（多文件 + Service Worker）
npm test             # 71 个单测，覆盖全部纯逻辑
npm run build        # 打成单文件 dist/petbloom.html
```

> 开发模式下 ES 模块与 Service Worker 需要 `http://` 才能加载，所以请用上面的本地服务器打开，不要直接双击 `index.html`。

## 想直接用：单文件版

`dist/petbloom.html` 是打包好的完整 App —— 一个 HTML 文件，**双击就能用**，没有任何外部请求（CSS 内联、JS 打成一个 IIFE、图标是 data URI），因此天生离线可用，也可以直接发给别人或放进任何静态托管。

- 手机上想当 App 用：在浏览器打开后「添加到主屏幕」
- 想装成 PWA（带图标与离线缓存）：用开发模式那份 `index.html`，它有 manifest 与 Service Worker
- `dist/` 按仓库既有约定不入版本库（根 `.gitignore` 忽略 `dist/`），克隆后跑一次 `npm run build` 即可生成

## MVP 验证的核心指标

方案里定下的一条判断标准：**用户在"宠物出现异常"时，是否愿意打开 APP 并完成 5 分钟症状自查。** 这一版把这条路径做完整了 —— 从首页的「它好像不舒服」入口，到判级、家庭护理、就医摘要与费用参考。

## 饮食引擎：为什么需要五套模型

"每天该吃多少"在不同物种上根本不是同一个问题，所以 `lib/nutrition.js` 按物种分派：

| 模型 | 适用 | 算法 |
| --- | --- | --- |
| 热量制 `kcal` | 猫、狗 | `RER = 70 × 体重^0.75`，再乘生理系数（幼年 2.5-3.0 / 已绝育成年 1.2-1.6 / 老年 / 减重…），然后拆成干粮克数、湿粮罐数与零食上限 |
| 配比制 `ration` | 兔、豚鼠、龙猫、仓鼠 | 干草无限量 + 叶菜与颗粒粮按每公斤体重折算。草食动物的核心不是热量而是纤维比例 |
| 占比制 `ratio` | 鹦鹉 | 颗粒粮 60-70% + 蔬菜 20-30% + 种子坚果 <10%，直接对着"只喂瓜子"这个最大的坑 |
| 猎物制 `prey` | 蛇 | 猎物重量为体重的 10-15%，间隔按阶段 |
| 节律制 `schedule` | 蜥蜴、龟 | 按阶段给投喂频率 + 钙粉/UVB 补充节律（缺钙缺 UVB = 代谢性骨病） |

还有两个日常最常用的小工具：

- **食物安全库**（`data/foods.js`）：每条记录给出**按物种区分**的结论。胡萝卜对狗是安全零食、对兔子是限量高糖食物、对龙猫应完全避免 —— 用一句"能不能吃"回答所有物种，本身就是错误来源。库里查不到时返回「资料不足」而不是「安全」。
- **粮食标签评测**（`gradeLabel`）：把包装上的营养成分保证值换算成干物质基础。这是看懂粮袋的关键 —— 湿粮标蛋白 10% 并不比干粮 32% 差，因为湿粮里 78% 是水。同时扫描配料表里的填充原料与争议添加剂。

## 判级引擎：物种差异必须显式建模

`data/triage.js` 里的规则带 `species` / `exceptSpecies` 限定，因为用同一套规则会害死其中一个物种：

- 兔子 12 小时不吃或便便变小 → **红灯**（胃肠停滞，24 小时内可致命）
- 蛇拒食 12 小时 → **绿灯**（蜕皮期与季节性拒食是正常的，改为盯体重）
- 猫用力排尿却尿不出 → **红灯**（尿道阻塞，最常被当成便秘耽误）；同样症状在犬不套用此规则
- 犬反复干呕 → **红灯**（警惕胃扩张扭转）；猫反复干呕 → **黄灯**
- 鸟只要出现可见异常 → **红灯**（鸟类会把病症隐藏到极限）

规则冲突时永远取最严重的一级。绿灯规则只在没有任何黄/红灯时才作为结论展示。

## 代码结构

```
petbloom/
├── index.html              外壳
├── manifest.webmanifest    PWA 清单（含"症状自查"快捷方式）
├── service-worker.js       离线缓存
├── styles/app.css          视觉系统 + 6 套物种主题 + 深色模式
├── scripts/
│   ├── serve.js            零依赖本地服务器
│   └── build-single-file.js 单文件打包（esbuild）
├── src/
│   ├── app.js              hash 路由（含 ?参数）+ 顶栏 + 主题字号 + 底部导航
│   ├── ui.js               模板拼接与转义 + toast + 对话框 + 入口行 + 时间轴（无框架）
│   ├── data/               species / foods / behavior / care / triage / myths
│   │                       knowledge / firstaid / guide / meta
│   ├── lib/                nutrition / triage / alerts / growth / projection
│   │                       reminders / search / finance / store
│   └── views/              onboarding home records nutrition behavior triage more
│                           knowledge firstaid reminders timeline health search
│                           guide settings about help
└── tests/                  node --test，全部针对纯函数层
```

数据层与逻辑层完全分离，且逻辑层都是纯函数 —— 内容会随兽医共识更新，改 `data/` 不需要碰 `lib/`，改 `lib/` 有单测兜住。

## 数据与隐私

所有记录只存在浏览器 `localStorage` 里，不上传。隐私模式下自动退回内存存储，不会崩。`更多 → 数据` 可导出 JSON 备份或清除全部数据。接后端时直接同步这份扁平 JSON 即可。

## 内容边界

- 判级引擎只输出**紧急度分级与行动建议**，不做疾病诊断，任何等级都保留"直接联系兽医"的出口。
- 免疫、体检、费用等数据是通用参考区间，会因地区、品牌与个体差异变化，最终以面诊兽医的方案为准。
- 行为方案全部基于正向强化，不含任何惩罚性手段。
- 上线前需要执业兽医对 `data/` 目录做一轮内容审核，这是方案里列的关键合规项。
