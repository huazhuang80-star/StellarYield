# BALANCE — 双向体重管理原型

《BALANCE》产品方案（见 [`docs/balance-nutrition-app-product-plan.md`](../../docs/balance-nutrition-app-product-plan.md)）的可运行原型。
单文件、零依赖、无后端 —— 直接用浏览器打开 `index.html` 就能用。

> ⚠️ 这与本仓库的 Stellar DeFi 协议代码无关，是一个独立的产品验证原型，放在 `apps/` 下与主工程隔离。
> CI 的 frontend / backend / contracts 任务分别只作用于 `client/`、`server/`、`contracts/`，不会扫到这里。

## 运行

```bash
open apps/balance/index.html          # macOS
xdg-open apps/balance/index.html      # Linux
# 或者拖进任意浏览器 / 手机上「添加到主屏幕」
```

数据全部存在浏览器 `localStorage`，不联网、不上传、无账号。清掉浏览器数据即清空。

## 已实现的功能

| 模块 | 状态 | 说明 |
|---|---|---|
| 双向调节 | ✅ | 减脂 / 增重共用同一套底层，随时切换。目标热量、食谱建议、成长形态、替代方案全部跟着换 |

| 节气食谱 | ✅ | 按当前日期算出所处节气，推送当季宜食 |
| 体重趋势 | ✅ | SVG 面积图，端点高亮 |

## 两处刻意的产品决策

### 1. 进食障碍筛查会关掉热量功能

引导流程内置 SCOFF 自评问卷。**命中 ≥2 项时不进入正常流程**，而是：

- 展示求助资源（危机热线、专科门诊指引）
- 关闭热量目标与体重打卡，切换为「结构模式」—— 只看吃得够不够齐，不显示任何数字
- 体质、节气、冲动急救仍可用（这些不涉及计数）

用户可以明确选择「我理解风险，仍要开启」，也可以随时在「我的」里改。
一个盯着卡路里的工具对进食障碍人群是有害的，这个门是产品的一部分，不是附加声明。

### 2. 不为了「增重」或「减脂」牺牲安全区间

- 减脂目标热量有下限：`max(BMR×1.1, 女 1200 / 男 1500)`，不会算出饿死人的数字
- 目标体重对应 BMI < 18.5 时明确警告并给出健康下限体重
- 当前 BMI 已 < 18.5 还要减 → 警告
- 增重模式下 BMI ≥ 24 → 提示把重点转向力量训练而非热量盈余

## 关于 AI 识别精度

产品方案里写「2.6 秒完成识别」，但真正的风险不是速度而是**准确度**：中餐同盘混炒、酱汁与油量不可见，单张照片的克重估算误差通常在 20%–40%。

这个数决定产品叙事到底是「精确热量」还是「趋势与结构」，而它会改变首页和识别页的整个信息层级。**建议在接 API 之前先用 500 张真实中餐照片测出误差分布**，再决定 UI 怎么做。

原型目前采取保守做法：份量默认值可改、鼓励手动修正，不把单餐热量当精确值呈现。

本原型提供生活方式建议，**不构成医疗诊断或治疗方案**。体质判定来自缩短版自评问卷，饮食宜忌基于中医传统理论的食性归类，均未经临床验证；热量数值为公式估算，个体差异约 ±10%。如有慢性病、进食障碍史、正在服药、怀孕或哺乳，请以医师意见为准。
